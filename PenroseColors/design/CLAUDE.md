## What this is

An exploration tool (step 1) for a later colour-sorting puzzle (step 2) inspired by "I Love Hue
Too": Penrose P3 tilings (thick and thin rhombs) coloured with a smooth gradient from a plane
through the HSL cone; the colours are shuffled and the player swaps tiles back into order.
Source of the idea: [vision.md](vision.md) (with four reference screenshots in this folder).

## Decisions taken in the discussion

- **Scope:** exploration tool in detail, to be built **quickly**; the game is only a provisional
  outline that will change after the inception phase with the tool.
- **Tiling:** P3 only, generated by **subdivision (deflation)** from seeds (sun, star, decagon
  wheel, mirrored halves). Inflation is not used for generation (not well defined at the boundary of
  a finite patch). Not chosen: de Bruijn pentagrid windows, clipping, P2.
- **Colouring:** position → colour on an HSL plane, plus radial / angular mappings; **continuous**,
  one colour per tile; every colour plane is allowed (no hue-range rules).
- **Sliders:** on-screen sliders for all colour parameters (live preview). URL parameters are the
  same settings; saving a setting = copy the URL. No export.
- **Uniqueness:** strict, mathematical (exact 8-bit sRGB ties and patch symmetries, minimal anchor
  set). Perceptual (ΔE) uniqueness and difficulty: step 2.
- **Swaps:** only tiles of the **same shape** swap (thick with thick, thin with thin), so players
  only sort colours and never worry about the shapes fitting. By **drag and drop** (mouse) and by
  two taps; touch works the same through pointer events.
- **Puzzle size:** minimum swaps beginner ≈ 30, medium ≈ 80, expert 150–200 (never more) →
  patches of about 20–250 tiles; the tool shows minimum swaps (tiles − cycles) and can shuffle to a
  target swap count.
- **Platform:** desktop browser first. The first idea (run from `file://`) was **dropped** on
  2026-10-22: it would forbid ES modules and service workers and make a later PWA a redesign.
  Instead `start.cmd` (done, committed) starts `server.mjs` (Node, `http://localhost:4175/`) and
  opens the browser. Plain ES modules like Sudoku; the same server serves the e2e tests. Touch also
  works; offline/PWA later by adding a manifest and a service worker.

## Idea to explore later (from the user, my opinion in PRD 13)

Colour variation by recursion level (e.g. +10 % saturation/lightness). Opinion: do it as colour by
**ancestor** (parent tile at each coarser level, a by-product of the subdivision), since all
tiles of a patch end at the same depth; it also breaks colour ties. A later exploration option.
