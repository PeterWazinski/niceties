## What this is

An exploration tool (step 1) for a later colour-sorting puzzle (step 2) inspired by "I Love Hue
Too": Penrose P3 tilings (thick and thin rhombs) coloured with a smooth gradient from a plane
through the HSL cone; the colours are shuffled and the player swaps tiles back into order.
Source of the idea: [vision.md](vision.md) (with four reference screenshots in this folder).

## Decisions taken in the discussion

- **PRD scope:** exploration tool in detail, the game only as an outline.
- **Tiling:** P3 only, generated by subdivision (deflation) from seeds (sun, star, decagon wheel,
  mirrored halves). Not chosen: arbitrary windows via the de Bruijn pentagrid, clipping to a
  shape, P2 or other tilings.
- **Colouring:** position → colour on an HSL plane, plus radial / angular mappings. Not chosen:
  tile-type channel as a main feature (kept as a small optional lightness shift), colour by graph
  distance. **Continuous only**: every tile has its own colour; no quantised palette.
- **Uniqueness:** *strict, mathematical*: exact equal 8-bit sRGB colours (ties) and symmetries of
  the patch; minimal anchor set as a hitting-set problem. Perceptual (ΔE) uniqueness is left open.
- **Tool features:** shuffle and manual solving; anchors and uniqueness check. The user did **not**
  select live controls/presets or export → colour parameters go through **URL parameters** instead
  (assumption of mine, flagged in the PRD; sliders would be a later change request).
- **Platform:** static web page, **touch first**, offline-capable (service worker), SVG rendering,
  same conventions as Sudoku.
- **Game outline:** show sorted, then shuffle; levels by tiling and number of anchors. Not chosen:
  explicit "no timer / no score" statement (left as an open question), tap-to-swap is assumed anyway
  because manual solving needs it.

## Assumptions of mine the user should confirm

1. Swapping exchanges **colours**, so thick and thin tiles may swap.
2. **Undo** is allowed in the tool (not necessarily in the game).
3. URL parameters instead of sliders and export for step 1.
4. Dark background for judging colours, as in the reference screenshots.
